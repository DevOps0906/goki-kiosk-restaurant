# 테이블오더 명세 — ② 나갈 때 결제 (고깃집 기본)

> 테이블마다 놓인 갤럭시탭(가로 1280×800). 규칙의 정본은 `docs/03-operation-modes.md`, 계산서 결제는 `specs/counter.md`.
> 화면 상단은 모든 화면 공통: 로고 · 가게 이름 · **테이블 번호 배지** · "결제는 나가실 때 카운터에서" · `주문 내역 (금액)` · `직원 호출`.

## 1. 대기 화면

- 디자인: [`to-00-idle`](../screenshots/to-00-idle.png)

**구성**

- 왼쪽: 가게 이름, **"이 자리는 12번 테이블"** (번호 크게), 대표 사진 · 오늘의 추천
- 오른쪽: "자리에서 바로 주문하세요", 안내 "결제는 다 드시고 나가실 때 카운터에서", `메뉴 보고 주문하기 ›`, `직원 호출`, `주문 내역`

**규칙**

- 계산서가 닫히면(결제 완료) 이 화면으로 돌아옴
- 메뉴 화면에서 1분 무입력이면 이 화면으로. 담아 둔 이번 주문은 유지

## 2. 메뉴

- 디자인: [`to-01-menu`](../screenshots/to-01-menu.png)

**구성**

- 왼쪽 분류: 전체 · 고기 · 식사 · 찌개 · 탕 · 사이드 · 주류 · 음료
- 메뉴 카드 4열: 사진 · 이름 · 단위 · 가격 · 담은 수량 · 품절
- 오른쪽 **이번 주문** 패널: `N차 주문` 배지, 줄마다 − + · 금액, 안내 "주문하면 바로 주방으로 가요. 결제는 나가실 때", 이번 주문 금액, `주문하기 ›`

**규칙**

- 고기 첫 주문은 최소 2인분(`docs/01` 1장). 이미 고기 주문이 있으면 1인분부터
- 이번 주문이 비면 `주문하기` 비활성
- 품절 메뉴는 누를 수 없음 (카운터 · 대시보드에서 품절 처리하면 바로 반영)

## 3. 주류 · 음료

- 디자인: [`to-01b-drinks`](../screenshots/to-01b-drinks.png)
- 19세 안내 배너 · `19` 배지 (`docs/01` 2장)

## 4. 주문 확인

- 디자인: [`to-02-confirm`](../screenshots/to-02-confirm.png)

**구성**

- 모달: "12번 테이블 · 3차 주문", "이대로 주방에 보낼까요?", 줄 목록, 이번 주문 금액
- 안내 상자: "지금까지 드신 금액 66,000원 + 이번 주문 = 104,000원 · 결제는 나가실 때 카운터에서"
- `더 고를게요` / `주문 보내기`

**규칙**

- `주문 보내기`를 누르면 버튼 비활성 → 서버 저장 성공 후 완료 화면 (중복 주문 방지: 주문마다 멱등 키 `{sessionId}-{round}`)
- 서버 연결이 끊겼으면 보내지 않고 "인터넷이 끊겼어요. 직원을 불러 주세요" (`docs/03` 7장)

## 5. 주문 전송 완료

- 디자인: [`to-03-sent`](../screenshots/to-03-sent.png)
- "주방에 주문을 보냈어요", 이번 주문 요약, **지금까지 합계(1~N차)**, `추가 주문하기` · `주문 내역 보기`
- 10초 뒤 메뉴 화면

## 6. 우리 테이블 주문 내역

- 디자인: [`to-04-history`](../screenshots/to-04-history.png)

**구성**

- 차수별 카드: `1차 주문 18:05` · 차수 합계, 줄마다 메뉴 · 수량 · 주방 상태(`접수` · `조리 중` · `나감`) · 금액
- 오른쪽: 지금까지 합계, "N번 주문 · 손님 4명 기준 1인 약 26,000원", 안내 "결제는 카운터에서 · 더치페이도 카운터에서", `계산 요청하기`, `추가 주문하기 ›`

**규칙**

- 카운터에서 취소한 줄은 취소선 + "취소됨"으로 남김 (금액 제외)
- 1인 금액은 착석 인원(카운터 입력, 없으면 숨김) 기준 참고값
- 주방 상태: MVP는 `접수`만. `조리 중` · `나감`은 KDS 연동 후 (2차)

## 7. 직원 호출

- 디자인: [`to-05-call`](../screenshots/to-05-call.png)

**구성**

- "무엇을 도와드릴까요?" 4×2 버튼: 불판 교체 · 숯 · 불 세기 · 물 · 앞치마 · 가위 · 집게 · 물티슈 · 반찬 리필 · 계산 요청 (여러 개 선택)
- 직접 쓰기 입력
- 오른쪽 보낸 요청 목록(`처리됨 18:40` · `가는 중`), `요청 보내기`, `닫기`

**규칙**

- 같은 항목을 처리 전에 다시 보내면 "이미 요청했어요" (`docs/03` 6장)
- `계산 요청` → 카운터 현황판 파랑 + 목록 맨 위
- 직접 쓰기 최대 40자

## 수용 시나리오

- [ ] 12번 태블릿: 돼지갈비 3인분 · 된장찌개 · 공깃밥 2 → 주문 보내기 → 주방 주문서 `테이블 12 · 첫 주문` 출력 → 카운터 현황판 12번 초록 54,000원
- [ ] 2차 물냉면 · 콜라 · 공깃밥 → 내역에 1차 · 2차, 합계 66,000원
- [ ] 3차 돼지갈비 **2인분** (추가라 최소 인분 안내 없음) · 공깃밥 · 소주 → 확인 모달에 "66,000 + 38,000 = 104,000원" → 주방 주문서 `추가` 표시
- [ ] 첫 주문에 돼지갈비 1인분만 담으면 "처음엔 2인분부터 주문할 수 있어요" 안내, 주문하기 비활성
- [ ] 주문 보내기 버튼 두 번 빠르게 탭 → 주문은 1건만 생성
- [ ] 직원 호출 `불판 교체` → 카운터 현황판 3번처럼 노랑 + 호출 목록에 표시 → 카운터 `처리` → 태블릿 보낸 요청 `처리됨`
- [ ] `계산 요청하기` → 현황판 파랑
- [ ] 카운터에서 결제 완료 → 12번 태블릿이 대기 화면으로 돌아감
- [ ] 와이파이를 끄고 주문 보내기 → 보내지 않고 직원 호출 안내
