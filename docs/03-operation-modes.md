# 03 운영 방식 · 테이블 계산서 규칙

> 운영 방식은 **업종이 아니라 매장 설정**입니다. 코드는 core 공통 기능으로 만들고(core `docs/12-operation-modes.md`),
> 이 문서는 식당 화면 기준의 동작 규칙입니다. 두 문서는 같은 내용을 말해야 합니다.

## 1. 세 가지 방식

| | ① 카운터 키오스크 | ② 테이블오더 · 나갈 때 결제 | ③ 테이블오더 · 주문할 때 결제 |
|---|---|---|---|
| 설정 값 (`stores.operation_mode`) | `counter_prepaid` | `table_postpaid` | `table_prepaid` |
| 주문 기기 | 카운터 · 입구 키오스크 | 테이블 태블릿 | 테이블 태블릿 |
| 주문 구분 | 호출번호 (`A-017`) | 테이블 번호 | 테이블 번호 |
| 결제 시점 · 장소 | 주문할 때 · 키오스크 카드 단말 | 나갈 때 · 카운터 | 주문할 때 · 손님 휴대폰 |
| 주문 → 주방 | 결제 승인 후 | **주문 즉시** | 결제 승인 후 |
| 매장 / 포장 | 고름 | 없음 (항상 매장) | 없음 |
| 디자인 | `sw-*`, HW 스탠드 | `to-*`, `ct-*` | `tp-*`, `to-*`, `ct-*` |

**옵션**

| 옵션 | 기본 | 내용 |
|---|---|---|
| ① 나갈 때 결제 (`counter_postpaid_enabled`) | 끔 | 켜면 ①에서 주문 확인 다음에 테이블 번호 입력(`sw-02b-table`) → 결제 없이 주방 전송 → ②처럼 계산서에 쌓임 |
| ② 휴대폰 선결제 허용 | 끔 | 켜면 ② 테이블 태블릿에도 "지금 휴대폰으로 결제" 버튼 (③ 흐름 재사용) |
| ③ 나갈 때 결제 허용 (`tp-03-pay` 하단 버튼) | 켬 | 휴대폰 결제가 어려운 손님은 주문만 보내고 카운터에서 결제 → 주문서 · 현황판에 `미결제` 표시 |
| ① + ② 함께 쓰기 | — | 입구 키오스크(①) + 테이블 태블릿(②)을 한 매장에서. 기기마다 역할 지정(`set-04c-pair`) |

## 2. 테이블 계산서 (열린 주문)

- 테이블에 **첫 주문이 들어오면 계산서가 열립니다** (`table_sessions.status = open`). 착석만으로는 열리지 않습니다.
- 같은 테이블의 이후 주문은 모두 이 계산서에 **차수(1차 · 2차 …)**로 쌓입니다. 차수는 주문 보내기 1번 = 1차.
- 계산서 금액 = 열린 계산서의 주문 합계 − 취소 − 쿠폰.
- 계산서는 **결제 완료 + 받을 금액 0원**일 때만 닫힙니다. 닫히면 테이블 태블릿은 대기 화면(`to-00-idle`)으로 돌아갑니다.
- 한 테이블에 열린 계산서는 하나뿐입니다.

### 테이블 상태 (현황판 색 · `09-table-state`)

| 상태 | 조건 | 현황판 색 |
|---|---|---|
| 빈 테이블 | 열린 계산서 없음 | 흰색 점선 |
| 식사 중 | 열린 계산서 있음 | 초록 |
| 호출 중 | 처리 안 된 직원 호출 있음 | 노랑 (식사 중보다 우선) |
| 계산 요청 | 손님이 `계산 요청` 호출 또는 카운터에서 계산 시작 | 파랑 (가장 우선) |

## 3. 주문 규칙 (②)

- 주문 보내기 전 확인 모달(`to-02-confirm`): 이번 주문 금액 + 지금까지 금액을 함께 보여 줌.
- 보낸 주문은 손님이 취소할 수 없습니다. 취소 · 수량 수정은 **카운터에서만**(`ct-02-bill`의 `취소`), 사유를 남깁니다.
- 주방 상태 표시(`to-04-history`): `접수` → `조리 중` → `나감`. MVP는 `접수`만 자동, 나머지는 2차(KDS 연동).
- 최소 인분(2인분)은 **그 테이블의 첫 고기 주문에만** 적용. 추가 주문은 1인분부터 (`docs/01` 1장).
- 테이블 태블릿 무입력 1분 → 대기 화면. 담아 둔 이번 주문은 유지(손님 교체가 아니므로).

## 4. 결제 규칙 (카운터 · ②)

- 결제 단위는 **계산서**입니다. 주문 건별 결제가 아닙니다.
- 전체결제 · 더치페이(N등분 · 메뉴별 · 금액) · 쿠폰은 core `docs/04` · `docs/06`을 그대로 씁니다. 대상 금액만 "계산서 받을 금액".
- 쿠폰은 계산서에 적용합니다 (core D4 안 A: 할인 후 금액을 나눔).
- 현금 · 계좌이체는 "결제 기록만" 남기는 수동 결제로 처리 (카드 승인 없음).
- 결제 도중 손님이 테이블 태블릿으로 추가 주문하면 → 카운터 화면에 "결제 중 새 주문 있음" 경고, 결제를 마친 뒤 **같은 계산서에 남은 금액**으로 이어서 받습니다.

## 5. 테이블 이동 · 합석 (`ct-03-move`)

| 동작 | 대상 | 결과 |
|---|---|---|
| 자리 이동 | 빈 테이블만 | 계산서가 새 번호로 이동, 원래 테이블은 빈 테이블 |
| 합석 | 식사 중 테이블 | 두 계산서를 하나로 합침 (차수는 시간순으로 다시 매김), 원래 테이블은 빈 테이블 |

이동 · 합석 후 두 테이블 태블릿 화면이 바로 바뀌어야 합니다(실시간 동기화).

## 6. 직원 호출

- 호출 항목은 업종 `labels`(식당: 불판 교체 · 숯 · 불 세기 · 물 · 앞치마 · 가위 · 집게 · 물티슈 · 반찬 리필 · 계산 요청) + 직접 쓰기.
- 호출은 카운터 현황판 오른쪽 목록 + 서빙 알림(선택)으로만 보냅니다. **출력하지 않습니다** (사장님 설정으로 출력 가능).
- 같은 항목을 처리 전에 다시 누르면 새 호출을 만들지 않고 "이미 요청했어요" 표시.
- `계산 요청`은 테이블 상태를 "계산 요청"으로 바꿉니다.

## 7. 인터넷 끊김

- 테이블 태블릿 → 서버가 끊기면 주문 보내기를 막고 "직원을 불러 주세요" 안내 (테이블 태블릿에는 로컬 대기열을 두지 않음 — 중복 주문 위험).
- 카운터 태블릿은 마지막으로 받은 계산서로 결제 가능, 결제 기록은 outbox 로 나중에 전송 (core `docs/01` 5장).
- 주방 프린터는 서버가 아니라 **카운터 태블릿이 출력 담당**(MVP). 카운터 태블릿이 꺼지면 출력 대기열에 쌓임.
